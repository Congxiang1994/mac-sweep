# 2026-09-16

## workbuddy-sweep 脚本二次优化（commit 638800a，已 push）

以本机 `~/.workbuddy`（1.8G）为例逐项排查，脚本可回收空间 **79.1M → 588.8M**（`--aggressive` 734.4M）。

### 关键排查结论（本机实测）

| 目录 | 大小 | 性质 |
|---|---|---|
| `logs/sandbox/20260916` | 432M | 沙箱会话日志 `sandbox_[center_]<pid>_{NNN.log,mmap3}`，按 PID 命名 |
| `plugins/marketplaces` | 149M | 市场清单 zip 解压产物（**无 .git**），`autoUpdate: true`，可重拉 |
| `logs/2026-09-16` | 109M | 今天的会话日志，正在写，不删 |
| `app/session/Cache` | 54M | Electron HTTP 缓存 |
| `plugins/cache` | 81M | **已安装插件，绝不能删**（installed_plugins.json 的 installPath 指向这里） |
| `binaries` | 717M | 托管运行时，不删 |

### 新增的 4 条规则

1. **`logs/sandbox/` 按进程存活判定**（最大头）— 沙箱日志是「今天」的，旧的「早于今天」规则完全抓不到。
   - 提取 `sandbox_(center_)?<pid>` 的 pid，`ps -p` → `kill -0` 兜底判存活，活着的一律跳过
   - 叠加 `SANDBOX_COOLDOWN_MIN`（默认 5 分钟）写入冷却，防 pid 复用/竞态
   - 非今天的日期目录（`YYYYMMDD` 格式）整体删
2. **`traces/` 改为按闲置时间**（默认 60 分钟）而非「早于今天」→ 多回收 45M
3. **`app/session/` Electron 纯缓存** → 57M，只删 `Cache`/`Code Cache`/`GPUCache`/`DawnWebGPUCache`/`DawnGraphiteCache`/`Shared Dictionary`；**不动** `WebStorage`/`IndexedDB`/`Local Storage`/`Partitions`（含登录态）
4. **散落 `.DS_Store`**（WB_HOME 下 3 层）

### 环境坑（重要）

- **`ps` 在 agent 沙箱里返回 `operation not permitted`**，`ps -p $pid` 全部失败 → 若只用 ps 会把**活着的沙箱会话误判为 dead 并删掉**。实测 `kill -0` 对同用户进程可用（`kill -0 1` 因非本人进程会失败）。脚本已实现两级判定。
- 本机 `~/.workbuddy/logs/sandbox` 里的活跃 PID 是 `58878`(center)、`59027`、`60022`。

### 脚本工程改进

- `WB_HOME` 可覆盖（便于在 `/tmp` 副本上试跑删除逻辑，不影响真实数据）
- `--aggressive` 开关（`plugins/marketplaces`）
- `TRACE_MAX_AGE_MIN` / `SANDBOX_COOLDOWN_MIN` 可调
- 输出按类别分组 + 清理前后占用对比 + 活跃日志提示
- 组删除用换行分隔多路径，兼容含空格路径（如 `app/session/Code Cache`）

### 验证方式

在 `/tmp/wbsweep-test` 造隔离副本（dead pid 999999 + center 888888 + 存活 pid 478），跑 `--apply` 确认：存活文件保留、其余全删。
