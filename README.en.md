## What is this

Five standalone cleanup scripts, one per app, all sharing the same interaction model and safety mechanisms:

| Script | What it cleans | Typical reclaim |
|---|---|---|
| `workbuddy-sweep.sh` | WorkBuddy logs / caches / finished sandbox sessions / telemetry traces | Hundreds of MB ～ GB |
| `chrome-sweep.sh` | Chrome caches / component packages / AI model caches / crash reports / privacy traces | Hundreds of MB ～ GB |
| `cherry-studio-sweep.sh` | Cherry Studio render caches / browsing caches / tracking residue / historical logs | Hundreds of MB |
| `wps-sweep.sh` | WPS CEF kernel caches / add-on packages / cloud-service logs / crash backups | Hundreds of MB ～ GB |
| `uninstall-residue.sh` | Orphaned data in `Application Support` / `Containers` / `Caches` left by uninstalled apps | Depends on uninstall history |

Anything outside these four categories — settings, accounts, documents, memories, databases — **is never generated by the scan rules in the first place**, not "generated then filtered".

## Quick start

```bash
git clone https://github.com/Congxiang1994/mac-sweep.git
cd mac-sweep

bash workbuddy-sweep.sh          # scan → list → you choose → move to Trash
```

Not sure yet? Look without touching anything:

```bash
bash chrome-sweep.sh --scan      # report only, zero interaction, zero file changes
```

### Picking from the list

After scanning you get a numbered list (with sizes and paths). The selection syntax is identical across all five scripts:

| Input | Effect |
|---|---|
| `yes` / `all` | Move everything to Trash |
| `1 3 5` · `1-4` · `1,3` | Only these items (renumbered each round) |
| `pick` | Confirm item by item (y/n) |
| `q` / Enter | Stop; untouched items stay as-is |

If items remain after a round, the script asks again until you say stop.

### Filters and CLI

```bash
bash wps-sweep.sh cef log          # only items whose name/path contains cef or log (union)
bash wps-sweep.sh cache --and 1000 # intersection: both terms required
bash wps-sweep.sh --only cef,log   # comma syntax, same as space-separated
bash wps-sweep.sh --clean cef --yes   # non-interactive cleanup (filters required)
bash cherry-studio-sweep.sh --aggressive  # also include mildly-costly targets
```

## How it works

**Scan → list → you choose → Trash.** No daemon, no config file — each script is a hard-coded list of "what lives where and can be safely regenerated".

Three independent safety gates:

1. **Scope gate** — `--clean` requires a scope; `--yes` requires filter terms. The "wipe everything in one word" path is deliberately sealed off.
2. **Hard defense list** — a second gate independent of the scan rules: any path whose basename hits the protect list (`Cookies`, `Preferences`, `backup`, `OfficeSpace`…) is rejected outright. Even a future scan-rule bug cannot touch these.
3. **Trash, not `rm`** — every deletion is a `mv` into `~/.Trash`. Second thoughts: just drag it back.

More design notes:

- **Zero dependencies**: only macOS built-in bash 3.2 and coreutils
- **Dual-locale verified**: every script behaves identically under `LC_ALL=C` and UTF-8 (all variable references use `${var}` to avoid the UTF-8 variable-name-swallowing pitfall)
- **Running-app detection**: you get a notice if the app is running; cache cleanup is usually safe, restarting the app afterwards is recommended
- **Small fry too**: `.DS_Store`, `*.wal` journals, `LOG.old` and friends are included — zero-byte files are skipped automatically

## Tests

```bash
bash tests/test-workbuddy-sweep.sh        # 174 assertions
bash tests/test-uninstall-residue.sh      # 188 assertions
bash tests/test-chrome-sweep.sh           # 134 assertions
bash tests/test-cherry-studio-sweep.sh    # 104 assertions
bash tests/test-wps-sweep.sh              # 126 assertions
```

**726 assertions, all passing.** Tests run fully isolated: a fake `HOME` and fake app directories are built under `/tmp`, real data is never touched. Every script asserts survival of its must-keep list (databases, Cookies, backups, fonts, credentials).
